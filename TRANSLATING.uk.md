# Переклад UA Shutdowns

[English](TRANSLATING.md) · **Українська**

Мови інтерфейсу та Chrome Web Store можна додавати незалежно від документації. Документація та описи GitHub-релізів підтримуються лише англійською й українською.

## Додавання мови інтерфейсу

1. Скопіюйте `_locales/en/messages.json` у `_locales/<мова>/messages.json`. Використовуйте [підтримувану Chrome назву каталогу](https://developer.chrome.com/docs/extensions/reference/api/i18n), наприклад `pl` або `pt_BR`.
2. Перекладіть значення `message`. Залиште ключі та назви підстановок без змін. Поле `description` пояснює місце й умови використання тексту. В українському словнику пояснення українські, в англійському — англійські. Для нової мови їх теж можна перекласти, щоб перекладачам було зручніше працювати.
3. Налаштуйте мовні метадані, описані нижче. Змінювати JavaScript або реєструвати мову в окремому списку не потрібно.
4. Виконайте `node scripts/check-locales.cjs` та `node --test tests/*.test.cjs`.
5. Перезавантажте розпаковане розширення й перевірте його в Chrome з потрібною мовою інтерфейсу: введення дати, календар, довгі підписи та текст поширення.

Chrome обирає словник за мовою свого інтерфейсу. Для відсутніх повідомлень використовується `default_locale` з `manifest.json`, зараз це англійська. Наші перевірки вимагають повних словників перед публікацією, щоб користувачі випадково не отримали інтерфейс із сумішшю мов.

### Ключі та контекст для перекладача

Використовуйте зрозумілі ключі `snake_case`, згруповані за функцією та призначенням: наприклад, `schedule_share_copy_error`, `address_form_city_placeholder`, `date_calendar_next_month_action`. Крапки та вкладені групи повідомлень не підтримуються стандартним форматом Chrome. Зміна формулювання не потребує перейменування ключа.

Словник використовує стандартний [формат Chrome messages.json](https://developer.chrome.com/docs/extensions/how-to/ui/localization-message-formats):

```json
{
  "schedule_share_address_accessible_label": {
    "message": "Поділитись графіком на $DATE$: $ADDRESS$",
    "description": "Назва кнопки поширення графіка конкретної адреси за вибрану дату для читачів екрана.",
    "placeholders": {
      "date": { "content": "$1", "example": "23.11.2026" },
      "address": { "content": "$2", "example": "Обухів, Миру, 17" }
    }
  }
}
```

- `message` — перекладений текст, який бачить користувач.
- `description` — пояснення перекладачу, яке не відображається в інтерфейсі.
- `placeholders` — іменовані змінні значення. Збережіть їхнє `content` (`$1`, `$2` тощо); приклади показують вигляд даних. Іменовані підстановки можна переставляти в реченні. Залишайте всі визначення підстановок, навіть якщо текст певною мовою використовує лише частину з них.

Не перекладайте збережені значення адрес: сайт ДТЕК очікує українські назви населених пунктів і вулиць. Англійське “Group” означає чергу відключень ДТЕК (наприклад, 5.2), а “Line” — лінію живлення будинку.

### Мовні метадані та дати

Ці записи налаштовують мову й не відображаються як речення:

| Ключ | Приклад | Призначення |
| --- | --- | --- |
| `locale_language` | `pt-BR` | Мовний тег BCP 47, що відповідає каталогу (`pt_BR`) |
| `locale_format` | `pt-BR` | Типова локаль дат і календаря для перекладу |
| `locale_week_first_day` | `1` | Резервний перший день тижня: неділя = 0, понеділок = 1, субота = 6 |
| `locale_date_day_token` | `ДД` | Позначення дня в підказці формату дати |
| `locale_date_month_token` | `ММ` | Позначення місяця в підказці формату дати |
| `locale_date_year_token` | `РРРР` | Позначення чотиризначного року в підказці формату дати |

Якщо мова інтерфейсу Chrome відповідає мові обраного словника, її регіональний варіант визначає порядок дати й календар. Інакше використовується `locale_format`. Введення дати використовує григоріанський календар та цифри ASCII; у сховищі дати завжди мають формат `YYYY-MM-DD`, а дні відключень визначаються за київським часом.

`schedule_share_date_text` зазвичай використовує `$FULL_DATE$` — повну дату, автоматично сформовану для локалі. Якщо мова потребує особливої граматичної форми, використовуйте `$WEEKDAY$`, `$DAY$`, `$MONTH$`, `$YEAR$`. Тоді перекладіть `schedule_share_weekday_0` — `_6` для речення, починаючи з неділі. Українська використовує їх, щоб зберегти форми на кшталт «у вівторок». Назви місяців формує `Intl` у контексті повної дати.

`dtek_region_<id>_name` та `dtek_operator_<id>_name` — назви для інтерфейсу. `dtek_region_<id>_short` — назва регіону в тексті поширення.

## Додавання мови Chrome Web Store

1. Спочатку додайте відповідний словник інтерфейсу, щоб ця мова стала доступною в магазині.
2. Скопіюйте `store/en/description.txt` у `store/<мова>/description.txt` та перекладіть його. Зберігайте звичайний текст, який можна вставити в магазин без перетворення Markdown. Уточнення про охоплення ДТЕК і конфіденційність мають залишатися коректними.
3. Назва та короткий опис беруться з `extension_name` і `extension_description` у словнику інтерфейсу, на які посилається маніфест. Обмеження Chrome — 75 та 132 символи відповідно.
4. Після завантаження ZIP із локалізаціями оберіть мову на вкладці Store listing кабінету розробника й вставте повний опис. За наявності додайте локалізовані скриншоти. Файли репозиторію не публікуються на сторінці магазину автоматично.

Дивіться [інструкцію Google з локалізації сторінки магазину](https://developer.chrome.com/docs/webstore/cws-dashboard-listing). Для нової мови інтерфейсу опис магазину необов’язковий; перевірка контролює вже наявні мовні каталоги магазину. У нових описах посилайтеся на одну з двох підтримуваних мов документації; не обіцяйте документацію мовою, якої немає.

## Документація та релізи

- Англійська: `README.md`, `CHANGELOG.md`, `TRANSLATING.md`.
- Українська: `README.uk.md`, `CHANGELOG.uk.md`, `TRANSLATING.uk.md`.
- Додавайте кожну версію до обох історій змін. GitHub Actions формує один двомовний опис GitHub-релізу: спочатку український, потім англійський. Якщо запису версії однією з мов немає або він порожній, публікація зупиниться.
- Нові мови інтерфейсу не потребують додаткових README, історій змін або перекладів GitHub-релізів.

Для перевірки формування описів релізів виконайте `python3 tests/release-notes.test.py`.
